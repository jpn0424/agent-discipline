# Core Rule 05: Execution Safety & Resource Hygiene (Git 安全與資源清理)

## 為什麼要制定此規則？ (Why)
未經確認的自動 Commit 會污染 Git Commit History；而使用 `rm -rf` 刪除測試暫存檔則無法復原，容易誤刪重要檔案。
外部系統裡的記錄還多一層代價：那些資料不只本次測試在看，而且多數外部系統沒有垃圾桶，抹除之後連使用者自己也還原不了。
輔助腳本與測試執行器同樣存在邊界風險：未驗證目標路徑即執行清理、以字元集函式剝除路徑前綴、或未隔離子行程位元碼，都可能覆寫來源目錄、把全倉庫 Git 狀態混入子目錄檢查，或在交付物內留下未追蹤的快取檔。

---

## 具體執行方式 (How)

### 1. Git Commit 紀律 (No Unauthorized Commit)
> [!IMPORTANT]
> **硬約束。** 照字面執行，沒有判斷空間——違反後不可復原或影響第三方。
- **未經指示不得 Commit**：`git commit` 只在使用者當次明確發出指令時執行，例如「請幫我 commit」。沒有收到這道指令就不執行。
- **Commit 前衛生檢查**：執行 commit 前必須核對 `git status`，確保沒有誤納暫存檔、密碼或 `.DS_Store`。

### 2. 測試檔案可復原清理 (`trash` CLI)
> [!IMPORTANT]
> **硬約束。** 照字面執行，沒有判斷空間——違反後不可復原或影響第三方。
- **不得使用 `rm -rf`**：清理測試或暫存檔案時不得使用，該指令不可復原。
- **使用 Trash 移至垃圾桶**：在 macOS 環境下，必須使用 `/usr/bin/trash <path>` 將檔案移至垃圾桶，確保隨時可手動復原；其他平台若未配置可復原刪除工具，應將檔案移至暫存隔離目錄或明確請求使用者指示，不得執行不可復原的直接永久刪除。

### 3. 測試資料與外部系統記錄邊界
> [!IMPORTANT]
> **硬約束。** 照字面執行，沒有判斷空間——違反後不可復原或影響第三方。
- 測試過程中產生的資料與外部系統記錄**預設全部保留**供查驗，除非使用者明確指示清理。
- 若奉命清理，先查詢確認當前狀態，且僅能使用該系統提供的**可逆狀態轉換**，例如作廢、撤銷、停用；不得直接修改資料庫抹除紀錄。
- 只清理本次測試自己產生的記錄，不得擴及他人或既有資料。

### 4. 腳本路徑防護、位元碼隔離與子目錄範圍 (Script Path, Bytecode & Scope Hygiene)

撰寫或執行會重建目錄、產出視圖或驗證產物的腳本時，判準是「**這支腳本若收到非預期路徑或在交付目錄內執行，會不會覆寫來源檔案或留下未追蹤殘留物**」。防範四類常見失誤：

- **路徑重疊與非空目錄防護**：凡涉及清理、重建或覆寫目標目錄的腳本，必須先解析來源與目標的真實路徑，拒絕等於來源目錄、包含來源目錄、位於來源目錄內部、指向既有一般檔案，或指向不含自建標記檔的非空目錄；移除檔案時遵循本規則第 2 節的可復原清理方式。
- **子行程位元碼隔離**：測試套件以子行程呼叫 Skill 或交付目錄內的 Python 腳本時，必須傳入 `-B` 或設定 `PYTHONDONTWRITEBYTECODE=1`，且於程序內動態載入模組前設定 `sys.dont_write_bytecode = True`，避免位元碼快取污染交付目錄。
- **路徑前綴與 `file://` URI 解析**：移除開頭 `./` 前綴必須使用正則如 `re.sub(r"^(?:\./)+", "", path)`，不得誤用字元集 `strip("./")` 而削掉 `.config/` 等隱藏目錄的前導點；解析 `file://` URI 時只解碼一次，並處理 Windows 磁碟機雙斜線形式如 `file://C:/...`。
- **Git 子目錄狀態過濾**：在 Git 子目錄下執行 `git status --porcelain -z` 時必須以 `git rev-parse --show-prefix` 過濾範圍，避免全倉庫變更混入局部判定。
