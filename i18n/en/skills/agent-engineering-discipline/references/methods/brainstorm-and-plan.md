# Brainstorm and Plan

When handling multi-step feature development or architectural refactoring, complete two phases before touching implementation files:

1. **Investigation**: Read the project's source code and existing design specifications to establish current facts and constraints. **Do not modify any code during this phase.**
2. **Implementation Plan**: Author `implementation_plan.md` in the project or artifact directory, specifying the goal, items requiring user review, open questions, and the exact list of files to be modified.

Once the plan is written, stop calling tools immediately and wait for the user to approve or revise it. For the authorization boundary during planning, see [Core Rule 02](../core-rules/02-authorization-boundary.md): when the user says "discuss first" or "confirm first," present the plan and stop without starting implementation.
