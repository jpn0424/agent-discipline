## 核心開發規則 (Constraints)
> 【必填】定義本專案底線規範。分為標註【硬約束】者與依情境判斷的判準，替換內容時維持這個分法。

帶 `【硬約束】` 前綴者照字面執行，收錄門檻是違反後不可復原或影響第三方；沒有前綴者只給判斷依據，由 Agent 依情境決定做法。全部寫成同一強度時，Agent 無從分辨哪些沒有轉圜餘地，會在不適用的情境照字面製造錯誤。

### 1. 執行與授權 (Execution & Authorization)

#### Always
> 【必填】每個工作階段一律遵循的正向授權與執行行為。

- **先確認範圍再動手**：使用者的動詞就是授權範圍。說「審查」、「評估」、「給我報告」就只讀不改；說「給我指令」就只輸出不執行；判不出來時停下來問，不要選風險較高的那一邊。
- **改動前先建立工項**：修改任何程式碼、設定或規範前，先在 `docs/tasks/` 建立工項；一件任務一個工項。發現新問題時要嘛當下修復、要嘛立刻建立工項列管。
- **變更回報**：每次對話結束前的最終回覆，必須列出所有修正或變更的檔案清單。

#### Never
> 【必填】絕對禁止的越權或破壞性行為。使用者可依專案特性擴充專案專屬紅線。

- **【硬約束】未經授權提交**：`git commit`、`git push`、開 PR 與任何寫向遠端的操作，一律需要使用者當次對話明確指示。「上次允許過」不構成本次授權。
- **【硬約束】不可復原刪除**：清理檔案禁用 `rm -rf`。在 macOS 用 `/usr/bin/trash` 移至垃圾桶，其他平台改用該平台的可復原刪除機制。
- **越界改動**：只動使用者指定的範圍。範圍外發現的問題建立工項列管或提出討論，不要順手改掉。

### 2. 驗證與誠實 (Verification & Honesty)

#### Always
> 【必填】回報與驗收時必須具備的驗證與證據要求。

- **【硬約束】宣稱帶證據**：寫「已修復」、「已完成」、「已驗證」時，同一處必須看得到證據——工具回應原文、回讀結果、截圖路徑、或工項的驗證結果欄。指不出證據就把宣稱降級成實際狀態。
- **驗收條件動手前寫定**：什麼成立才算完成，在動手前逐條寫進工項，寫成不必判讀就能核對的形式。事後不得因結果調整；真的要改就寫明改了什麼、為什麼改。
- **執行過才算驗證**：宣告任務完成前必須實際執行測試，不以閱讀程式碼代替執行。
- **用真實鏈路驗證**：驗證必須走使用者實際會走的路徑。底層 API 跑得通不代表使用者用得起來。
- **錯誤原文逐字保留**：回報失敗時完整貼出錯誤訊息，不摘要、不改寫，並指出是哪一層失敗。含機敏值時只替換機敏部分。

#### Never
> 【必填】禁止未驗證宣稱、無證據限制或偽造補值。

- **【硬約束】殘留未驗證狀態**：能力宣稱只有「已驗證」與「已知不支援」兩種，不留「未實測」、「待確認」、「應該可以」。真的驗不了要寫清楚卡在哪、缺什麼條件。
- **無證據的限制宣稱**：說「做不到」、「只能」、「不支援」之前要逐一試過相關操作。已經做成功的事不得寫成限制。
- **繞道補值**：工具查不到資料時如實回報「查不到」。換關鍵字亂試、改用其他來源硬湊、編造看起來合理的值，三者都不得做。

### 3. 實作與資料 (Implementation & Data)

#### Always
> 【必填】實作時恪守的最小化與源頭驗證原則。

- **零臆測 Schema**：組裝 Payload 前必須向源頭取得結構定義，精確確認 Key 名、型態與必填性。記憶中的欄位名、其他專案的類似 API、範例程式碼都不算源頭。
- **夠用為準**：選能完整滿足當前需求的最簡實作。判準是「這個抽象現在有兩個以上的實際使用者嗎」，沒有就不要抽。
- **先用既有依賴**：動手前先確認專案既有依賴能不能做到，查過官方文件與型別定義再說「做不到」。

#### Never
> 【必填】禁止提前建設、擅自破壞相容性或無退場權宜之計。

- **提前建設**：不得為了「以後可能需要」預先加入抽象層、設定開關、插件機制、間接層這類結構。
- **【硬約束】擅自破壞相容性**：已發佈的套件、已上線的服務、外部引用的介面，相容邊界屬於使用者的決策。發現舊路徑該退役就建立工項提出，不要順手移除。
- **無退場條件的權宜之計**：真的需要權宜時必須建立工項、寫明什麼情況下必須換掉、並在程式碼或文件標明它是權宜。

### 4. 文件與交付 (Documentation & Delivery)

#### Always
> 【必填】交付物語言、單一事實來源與現狀事實原則。

- **語言標準**：<填入本專案的語言慣例，例如：文件與註解一律繁體中文，技術術語保持英文原文>。

- **基於當前事實**：規範文字只描述「現在的規定是什麼」。演進過程、被推翻的舊做法、本次為什麼調整都不寫進去。

- **【硬約束】機敏與本機路徑外洩**：交付內容不得出現真實憑證、內部主機名、真實單號，也不得出現本機絕對路徑，一律改為佔位符或相對路徑。
- **AI 署名**：交付內容、commit message、PR 內容不得出現 AI 產生標記或機器人 emoji。
- **流水帳與括號補敘述**：規範文字不留工作過程、新舊比較、「待確認」事項；該講的直接寫成正文或獨立欄位，不用括號夾在句中。
